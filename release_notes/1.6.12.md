# 1.6.12

- Fixed: "Auth Session Missing" error when trying to register a phone number for SMS verification — session is now validated and refreshed before returning the current user
- Fixed: password reset security issue — recovery session is now invalidated immediately after the password is changed, and the user is redirected to sign in instead of being left authenticated as the reset target account
- Feature (QA): new Cars tab — vehicle listings hub with search/filter bar, status chips (New / Pre-Owned / Certified Pre-Owned), and a vehicle card list; replaces the previous direct-to-filter navigation
- Feature (QA): Add Listing screen — form to create a vehicle listing (stock, VIN, make/model/trim/year, specs, pricing, location, photos); photos are picked from the device and uploaded to storage, matching the org photo upload flow

# Detailed Changes

### Auth Session Missing fix (`lib/services/api/supabase_api_service.dart`)

- `getCurrentUser()` now checks `_client.auth.currentSession` after finding a cached `currentUser`; if the session is null (access token expired but cache not yet cleared), it attempts `refreshSession()` before returning — this eliminates the window where `updateUser()` / RPC calls throw `AuthSessionMissingException` (BUG-004 / BUG-005 root cause)
- If refresh fails, returns `null` so the caller correctly sees the user as unauthenticated

### Cars tab — vehicle listings hub (QA only)

- `lib/modules/cars/vehicles_screen.dart` (new): `CarsVehiclesScreen` replaces the old direct push to `CarsSearchScreen`; rendered inside the main scaffold's offstage navigator so the bottom nav bar stays visible, matching Home / Messages / Directory behaviour
- Search bar taps open `CarsSearchScreen` (the existing filter panel); status chips filter the list client-side without a re-fetch
- Vehicle cards show the first photo (or a make-labelled placeholder), title, color/body/mileage/fuel details, price with optional strikethrough promotion price, status badge, and lot location
- `lib/modules/cars/vehicle_listing.dart` (new): `VehicleListing` model with `fromJson` / `toJson`; comma-separated `images` / `videos` strings are split into `List<String>` on parse and rejoined on save
- `migrations/071_vehicle_listings.sql` (new): `vehicle_listings` table with all 29 fields from the LiftKit vehicle spec; RLS — authenticated users can read, admins/superadmins can insert and update, only superadmins can delete; `updated_at` auto-trigger

### Add Listing screen (QA only)

- `lib/modules/cars/add_vehicle_screen.dart` (new): grouped form (Basic Info, Vehicle, Specs, Appearance, Pricing, Details, Options & Packages) with make/model dropdowns sourced from `CarData`, validated required fields, saves to `vehicle_listings` via Supabase
- Photos section uses `ImagePicker().pickMultiImage()` + `SupabaseApiService.uploadGenericFile()` — identical to the org photo upload flow; uploaded URLs are collected in memory and joined with commas on save; thumbnails show in a horizontal scroll strip with individual ✕ remove buttons
- Form fields override the app-wide `InputDecorationTheme` fill colour (`Color(0xFFE6E3DF)`) with `fillColor: Colors.transparent` so fields blend into the white card sections

### Password reset security fix (`lib/modules/auth/reset_password_screen.dart`)

- After `setNewPassword()` succeeds, `signOut()` is called immediately to invalidate the Supabase recovery session — prevents the recovery token from remaining active after the password change (BUG-007)
- Success dialog now dispatches `CheckAuthStatusEvent` (routes to welcome/login) instead of pushing `/home` directly, so the user is never silently left authenticated as the reset-target account
