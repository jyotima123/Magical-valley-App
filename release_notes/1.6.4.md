# 1.6.3

- Fix follower counts shown in All Channels being stale; counts and follow status now computed live from the database via a new `organizations_overview` view
- Fix grammar in organization followers screen
- Fix Direct Messages chat not opening when navigating from the Explore or Channels screen
- Fix missing back button in Direct Messages chat on narrow screens
- Fix unread indicator persisting after opening a Direct Messages conversation

# Detailed Changes

### Direct Messages: chat not opening from Explore/Channels

`openConversationWithOrganization` previously awaited `_loadConversations()` before navigating (~600 ms), creating a window where concurrent user interaction could set `_isNavigatingToChat = true` and silently block the programmatic navigation. The fix navigates immediately after the API call resolves and runs `_loadConversations()` in the background. The flag is also explicitly reset to `false` at the start of `openConversationWithOrganization` and `openConversationById` so a stuck value from a prior session can never block subsequent calls.

### Direct Messages: missing back button on narrow screens

`_startNewConversation` and `_startNewConversationAsAdmin` set `_selectedConversation` regardless of screen width. On narrow screens this caused `_buildNarrowScreenLayout` to render the inline `_buildChatView` — a plain `Column` with no `AppBar` or back button. All three navigation paths (`openConversationWithOrganization`, `_startNewConversation`, `_startNewConversationAsAdmin`) now call `_navigateToChatView` on narrow screens, which pushes `_ChatScreen` (with its explicit back button) onto the inner Navigator. `_buildNarrowScreenLayout` no longer renders the inline chat view; it always shows the conversations list.

### Direct Messages: unread indicator not clearing on open

The unread dot was driven by `conversation.hasUnreadMessages` (`unreadCount > 0` from the database), which only cleared after `markDirectMessagesAsRead` completed and the real-time stream re-emitted the conversation. On slow connections this left the dot visible even after the user had read the messages. The fix adds a client-side read-time layer using `SharedPreferences`: when any conversation is opened, `DateTime.now().toUtc()` is stored under `dm_last_read_<conversationId>`. The dot is now shown only when `lastMessage.createdAt` is after the stored timestamp, so it disappears immediately on open regardless of server latency. On first open (no stored timestamp) it falls back to `conversation.hasUnreadMessages`.
