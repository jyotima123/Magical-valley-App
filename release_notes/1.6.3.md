# 1.6.3

- Fix Post Views debug screen showing 0 counts for views and followers
- Fix View Rate and "Viewed by" count showing total views instead of unique viewers; total view count now shown separately
- Restrict Post Views Debug screen to superadmins, visible in all environments

# Detailed Changes

### Post Views debug screen: 0 counts fix

The `post_views` query in `QAPostViewsDebugScreen` used a `user_profiles!inner(*)` PostgREST join. An inner join requires the FK relationship to be declared in PostgREST and for RLS policies to permit the joined table access; if either condition isn't met, the entire query returns zero rows — causing every post to report 0 views and 0 followers.

The fix removes the inner join and fetches `post_views` with only raw columns (`user_id`, `viewed_at`), then resolves viewer profiles in a separate `user_profiles` query using `inFilter`. The redundant duplicate posts query (posts were fetched twice) was also removed.

Additionally, `post_views` has RLS enabled with only an INSERT policy and no SELECT policy, so every direct client query returns zero rows. A `SECURITY DEFINER` RPC function `get_post_views()` was added (migration 060) that bypasses RLS server-side and enforces superadmin/org-admin access in the function body. The screen now calls this RPC instead of querying the table directly.

### Post Views debug screen: unique viewer counts

`viewerCount` was previously set to `views.length` (total views, including repeated views from the same user). It is now `viewerIds.length` (deduplicated set of users). The post card badge, `% viewed`, and org-level View Rate all now reflect unique viewers. Total view count (including repeats) is still shown after `% viewed` on each post card for reference.

### Post Views Debug screen: superadmin-only, all environments

The menu item was previously inside the QA-flavor guard. It is now shown in all environments but restricted to users with the `superadmin` role.
