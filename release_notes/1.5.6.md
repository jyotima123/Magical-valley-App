# 1.5.6

- Keyboard "Next" action on auth forms now moves focus to the next field (login: email → password; signup: full name → email → password → confirm password)
- Fixed SMS verification failing with "Database error saving new user": `handle_new_user` DB trigger now skips profile creation for phone-only auth users (migration 056)
- Fixed SMS verification using wrong Supabase API: switched from `signInWithOtp` (creates orphaned phone-only user) to `updateUser` + `OtpType.phoneChange` to correctly link phone to the existing authenticated account
- Fixed email verification path: now explicitly sends OTP via `signInWithOtp` (unauthenticated) instead of relying on Supabase's signup confirmation email, which is no longer sent when email confirmations are disabled
- Fixed signup profile creation attempting a redundant DB insert (profile is already created by the `handle_new_user` trigger)
- Fixed signup form validation errors (e.g. passwords don't match) incorrectly navigating back to the welcome screen on dismiss — form now stays open so the user doesn't lose their name/email
- Fixed SMS verification choice button not opening the phone input — caused by Supabase firing `signedIn` immediately after signup (email confirmation disabled), which triggered `CheckAuthStatusEvent` and overrode `AuthVerificationMethodChoiceState` with `AuthAuthenticatedState`
- Added `verified_at` column to `user_profiles` (migration 057): `CheckAuthStatusEvent` now routes users with `verified_at = null` back to the verification choice screen, persisting the requirement across app restarts
- Added `sms_verification_enabled` feature flag (migration 058): SMS verification option is hidden by default and enabled per-environment via the `feature_flags` table (prod and QA are separate Supabase projects so each is configured independently)
- Fixed Apple/Google/Facebook login users being incorrectly routed to the OTP verification screen on app restart: `_onCheckAuthStatus` now reads `app_metadata.provider` and skips verification for social logins; `handle_new_user` trigger (migration 059) sets `verified_at = NOW()` immediately for non-email providers; existing social users are backfilled
- Fixed safe degradation when migration 057 has not been run: `UserProfile.fromJson` now uses `json.containsKey('verified_at')` to distinguish a missing column (migration not run → treat as pre-verified) from an explicit null (new user awaiting OTP → require verification)
- Fixed issue where org admins could not see their message button (now both categories_grid_scree and organizations_screen read the userProfile.role directly from AuthBloc state)
- Fixed `Error loading channels` error
