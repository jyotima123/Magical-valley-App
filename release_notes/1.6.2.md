# 1.6.2

- Fix channel list showing wrong last message when the latest post is pinned
- Fix sign-up form fields being cropped by keyboard on iPhone Pro models
- Fix stale cache issue causing deleted channels/organizations to remain visible (cache now expires after 24 hours)
- Improve sign-up form UX: fields progressively reveal as the user advances, with Back/Next buttons for keyboard navigation
- Group direct message conversations by organization for admins/superadmins managing multiple organizations

# Detailed Changes

### Channel list last message fix

`_getLastMessageForChannel` in `ChatService` previously fetched only posts with `status: 'active'`, which excluded pinned messages (`status: 'fixated'`). When the most recent post in a channel was pinned, the list would incorrectly show the previous unpinned message.

The method now fetches both statuses in parallel and returns whichever message has the later `created_at` timestamp, ensuring the channel list always reflects the true latest post regardless of pin state.

### Sign-up keyboard scroll fix

On iPhone Pro and other tall devices, the Password and Confirm Password fields in the sign-up form could be hidden behind the software keyboard because the scaffold uses `resizeToAvoidBottomInset: false` (required for the animation layout). The `SingleChildScrollView` in `_buildSignupForm` now applies a bottom padding equal to `MediaQuery.of(context).viewInsets.bottom`, giving the scroll area enough room to bring the focused field fully above the keyboard.

### Sign-up form progressive field reveal

When the keyboard opens on the sign-up form, fields are now revealed progressively as the user advances: only the current field and the next unvisited one are shown at a time. Fields the user has already filled remain visible. A Back/Next button row appears at the bottom of the form for keyboard navigation between fields, switching to a Sign Up button when the last field is reached. The buttons are tied to keyboard visibility (not focus state) so they remain reliably tappable throughout the session.

### Direct messages grouped by organization for admins

When an admin or superadmin manages more than one organization, the Direct Messages list now groups conversations under a section header per organization (sorted alphabetically). Admins managing a single organization continue to see a flat list as before.

### Organizations/channels cache expiration

`LocalCacheService` already stored a `updated_at` timestamp for each cached category, but `OrganizationsBloc` never checked it. The `canServeFromCache` condition now also verifies that the cache is less than 24 hours old. If the cache is older than 1 day (or has no timestamp), a fresh network fetch is triggered regardless of the stored count, preventing stale/deleted channels and organizations from persisting on device.
