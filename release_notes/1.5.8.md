# Detailed Changes

### Fix 4 — Email rate limit handling & SMS fallback

`AuthResult.error(msg)` stores the message in the `message` field, but the signup handler in `auth_bloc.dart` was reading `result.error` (always null), causing the fallback string `'Account creation failed'` to always be shown instead of the actual API error.

Two improvements on top of that fix:

- `_handleAuthException` now detects `over_email_send_rate_limit` (429) and returns a specific message instead of the generic "Too many requests".
- When signup itself is rejected due to email rate limiting, the service now returns `AuthResult.pendingEmailConfirmation` instead of an error, routing the user to the verification choice screen. Since the SMS button on that screen is only gated by the `smsVerificationEnabled` feature flag (not by email availability), the user can proceed with SMS verification even when the email service is unavailable.
