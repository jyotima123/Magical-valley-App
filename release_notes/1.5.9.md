# 1.5.9

- Fix SMS OTP verification bouncing user back to verification choice screen
- Fix triple-submit on phone OTP verification button
- Fix permanent bounce on next launch when profile update fails after phone verification

# Detailed Changes

### Fix 1 — Triple submit guard

`_onVerifyPhoneOtp` had no guard against duplicate events. If the user tapped the submit button multiple times before the first call returned, multiple `VerifyPhoneOtpEvent`s were queued simultaneously. The first call consumed the OTP token; the subsequent ones got "Token has expired or is invalid". Added an early return when `currentState.isLoading` is already true.

### Fix 2 — Race condition with `signedIn` auth event

When `verifyOTP(type: phoneChange)` succeeds, Supabase immediately fires `AuthChangeEvent.signedIn`. The global `_setupAuthListener` in `main.dart` was dispatching `CheckAuthStatusEvent` on every `signedIn` event — including this one. At that moment `verified_at` had not yet been written to `user_profiles` (the `updateUserProfile` call was still in-flight), so `_onCheckAuthStatus` saw `verified_at: null` and bounced the user back to the verification choice screen. Fixed by skipping `CheckAuthStatusEvent` in the listener when the bloc state is already `AuthPendingPhoneVerificationState`.

### Fix 3 — Permanent bounce on next launch

If the `updateUserProfile` call that writes `verified_at` fails (e.g. a transient network error), the user would be bounced to the verification choice screen on every subsequent app launch even though their phone was confirmed in Supabase.

Two changes to address this:
- `getCurrentUser()` now includes `phone_confirmed_at` from the Supabase session in the returned `userData`.
- `_onCheckAuthStatus` treats a non-null `phone_confirmed_at` as equivalent to `verified_at` being set. If the phone is confirmed but `verified_at` is missing in the profile, it backfills it automatically so the issue self-heals on the next launch.
