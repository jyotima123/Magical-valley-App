# 1.6.15

- Feature (QA): dealer inventory in Cars — vehicles from the LiftKit feed now appear in the Cars tab **above** the community listings, marked with a *Dealer* badge, and open a "View at Dealer" link to the dealership's own vehicle page instead of the Call / Message Seller actions
- Feature (QA): the two sources fail independently — if the dealer feed is down the community listings still load (and vice versa) behind a retryable amber banner; only a total failure shows the error screen
- Feature (QA): infinite scroll in Cars — the list now reveals 20 vehicles at a time and loads the next page as you approach the bottom, ending with a "Showing all N vehicles" marker
- Fix (QA): a missing price no longer renders as `$0` — dealer feeds routinely omit the price on fresh trade-ins, which now show **"Call for price"** (39 of the 112 live vehicles are in this state)
- Fix (QA): search and filter chips now match dealer vehicles — the feed's own vocabulary ("Used", "Gas", "Four Wheel Drive", body "Wagon" on every SUV) is normalized to the app's `CarData` options, otherwise selecting any status/fuel/body chip hid the entire dealer inventory
- Fix: iOS archive builds on Xcode 26+ — `compile_ios.sh` pre-builds the Flutter framework so `ScanDependencies` can resolve `Flutter/Flutter.h` before the build-phase scripts run; `AppFrameworkInfo.plist` gains `LSMinimumSystemVersion 15.6` and the SwiftPM `Package.resolved` files are now committed
- ⚠️ Security note for review: `LIFTKIT_KEY` is read on-device from `.env_prod`, which `pubspec.yaml` ships as a Flutter asset — the key is extractable from any built APK/IPA. This predates 1.6.15 (the file was already bundled), but LiftKit's docs explicitly say not to expose the key client-side. See the follow-up note at the end of this file.

# Detailed Changes

### LiftKit dealer feed (`lib/modules/cars/liftkit_api_service.dart`, new)

- `LiftKitApiService`: read-only client for `GET https://api.liftkit.io/api/v1/vehicles` authenticated with `X-API-Key` from `dotenv['LIFTKIT_KEY']`; walks all pages (100 per request, hard stop at 20 pages) using the `meta.has_more` field with the `X-Has-More` header as fallback, and de-duplicates by stock/VIN across pages
- Absent key = feature off: `.env_qa` has no `LIFTKIT_KEY`, so QA silently shows community listings only rather than erroring
- 10-minute in-memory TTL cache, so returning to the Cars tab or bouncing off a detail screen costs zero requests against the documented 60 req/min limit; pull-to-refresh passes `forceRefresh: true` to bypass it
- `LiftKitException` carries a user-facing message per status: 401 (key missing) / 404 (key invalid or feed inactive) / 429 (rate limited) / 500 / timeouts and connection errors ("Could not reach dealer inventory.")
- `LiftKitVehicleMapper`: maps the feed onto `VehicleListing`. **The live response does not match the flat field table in the LiftKit docs** — response shape is dictated by the dealer's own feed mapping, and this dealer returns nested `color{}`, `engine{}`, `transmission{}`, `pricing{}`, `description{}`, `photos[]`, `year` as a string and `vehicle_acquired` as a Unix epoch. Mapping is a separate class from the transport so it is testable without network
- Vocabulary normalization (each verified against the full 112-vehicle inventory, zero unmapped values):
  - `status`: `certified: true` → *Certified Pre-Owned*; `new` → *New*; everything else → *Pre-Owned* (the feed says "Used", which matches no status chip)
  - `body`: `type` wins over `body` for SUV/Truck — the feed labels all 65 SUVs with body "Wagon"; remaining bodies map to Pickup Truck / Passenger Van / Minivan / Sedan / Coupe / Convertible / Hatchback / Wagon / Crossover, falling back to the raw value so oddities like RV survive
  - `fuel`: gas / gasoline / unleaded → *Gasoline*, plus Diesel / Hybrid / Plug-in Hybrid / Electric / Flex Fuel / Hydrogen
  - `drivetrain`: Front / Rear / All / Four Wheel Drive → FWD / RWD / AWD / *4WD / 4x4*
  - `pricing`: `original` > `final` is treated as a discount (`price` + `promotion`); currency formatting like `$59,923.00` is stripped before parsing
  - `description`: `<br>`/`</p>`/`</div>` become newlines, remaining tags are stripped and HTML entities unescaped
  - `features`: curated `key_features` first, de-duplicated against the ~283 OEM option strings
- Vehicles with neither stock number nor VIN are skipped rather than given a synthetic id

### Vehicle model (`lib/modules/cars/vehicle_listing.dart`)

- New `VehicleSource` enum (`community` / `liftkit`) with an `isFromDealerFeed` getter — the discriminator every dealer-specific branch reads
- New fields: `vdpUrl` (dealer's own vehicle detail page), `drivetrain`, `features`
- `hasPrice` / `displayPrice`: a zero price now renders **"Call for price"** instead of `$0`
- Dealer ids are namespaced `liftkit:<stock>` so they cannot collide with our own rows

### Cars list (`lib/modules/cars/vehicles_screen.dart`)

- Both sources are requested concurrently and merged as `[...dealer, ...community]`, so dealer inventory leads the list; the default *Most Relevant* sort preserves that order, and an explicit sort overrides it
- Independent failure handling: one source failing shows `_NoticeBar` (amber, with Retry) above the other source's results; only both failing produces `_ErrorState`
- `_DealerBadge` (storefront icon + "Dealer") on cards mirrored from the feed
- **Infinite scroll**: results are revealed `_pageSize = 20` at a time; a `ScrollController` listener extends the window once within 400 px of the end, so the list grows before the user reaches the bottom. A post-frame guard stops a fling from revealing several pages against a not-yet-grown scroll extent
- A page here is a **render window, not a fetch** — both sources stay fully loaded because filtering and sorting run across the merged list, and paging the requests would silently break cross-source sorts like *Lowest Price*
- Filtering moved from a getter to a `_matches` field recomputed by `_recomputeMatches()`. It previously re-ran the full filter + sort on every rebuild, which with scroll-driven rebuilds would have meant a full pass per scroll event
- Paging resets deliberately: changing the search text, a status chip or the filter sheet returns to page 1 at the top; a *reload* does not, so returning from a vehicle detail screen keeps the user's place instead of dumping them back at the top of page 1
- `_ListFooter`: spinner while pages remain, otherwise "Showing all N vehicles"

### Vehicle detail (`lib/modules/cars/vehicle_detail_screen.dart`)

- Dealer listings are routed away from every path that assumes a row in `vehicle_listings`: `_reload()` returns early, and Edit / Mark-as-Sold stay hidden because `createdBy` is null for feed vehicles
- Call / Message Seller is replaced by a full-width **"View at Dealer"** button opening `vdpUrl` externally (present on 100% of the live feed), with a red snackbar if the URL cannot be launched, plus a footnote: "Dealer inventory — details come from the dealership and may change without notice"

### Search filters (`lib/modules/cars/vehicle_search_filters.dart`)

- The fuzzy haystack now also covers `drivetrain` and the feed's `features` list, so drive-type and feature chips match dealer vehicles
- Those ~283 option strings per vehicle made a full filter pass cost ~30 ms (a couple of dropped frames per keystroke while a drive-type/feature/condition filter was active). The haystack is now built once per listing into an `Expando<String>` cache — measured back down to ~0.4 ms steady-state
- New `_loose()` normalization drops the spacing around `/` and `-` so chip labels match feed values (`Apple CarPlay / Android Auto` vs `Apple CarPlay/Android Auto`)

### Tests

- `test/liftkit_vehicle_mapper_test.dart` (new, 9 tests): full-shape mapping, vocabulary normalization, certified promotion, the SUV-labelled-as-Wagon case, HTML/entity stripping, discount pricing, missing price → "Call for price", null on missing identity, VIN fallback
- `test/vehicles_screen_pagination_test.dart` (new, 4 tests): drives the real screen with a `MockClient`-backed Supabase — only the first page is reachable before scrolling, scrolling reveals every page through to the end marker, short result sets show the marker immediately, and a mid-scroll search returns to the top and restarts paging
- `http` added to `dev_dependencies` for `MockClient`
- Two traps worth knowing when writing widget tests against Supabase screens: `postgrest` hands responses over ~10 KB to a background isolate that **never completes** under `flutter_test`'s fake async (the screen just sits on its spinner — hangs rather than fails, so the fixture size is guarded by an `expect`), and `MockClient` responses must be constructed with `request: request` because `postgrest` dereferences `response.request` while parsing
- Pre-existing and unrelated: `test/widget_test.dart` ("Counter increments smoke test") still fails — it is the untouched stock Flutter template test that boots `MyApp` without Supabase initialized
