# 1.6.6

- Integrate Amplitude analytics with API key configuration
- Track tab navigation events (Home, Messages, Manage, Directory)
- Track channel chat open and close events
- Track direct message chat open/close and conversation start/error events
- Track auth events: sign-up, login errors, social login errors
- Track user actions: follow/unfollow channel, post reactions, direct messages sent, profile updates, feedback submissions
- Track profile settings screen item taps (edit profile, feedback, terms, privacy, sign out, etc.)
- Track notification badge updates with unread count and total channel count
- Identify users in Amplitude using their username; set email and role as user properties

# Detailed Changes

### Amplitude integration

A new `AmplitudeService` singleton (`lib/services/amplitude_service.dart`) wraps the `amplitude_flutter` SDK (already present in `pubspec.yaml`). It exposes `initialize()`, `setUserId()`, `setUserProperties()`, `logEvent()`, and `reset()`. The service is initialized at app start in `main()`, after Supabase is ready.

### User identification

When `AuthAuthenticatedState` is emitted with a loaded `UserProfile`, `AmplitudeService.setUserId` is called with the user's **username** (human-readable and unique), and `setUserProperties` is called with `email` and `role`. This happens in `_handleAuthStateTransition` in `_AppRouterState`. On sign-out, `AmplitudeService.reset()` clears the identity.

### Tab navigation tracking

`tab_viewed` is fired in the `BottomNavigationBar.onTap` callback in `MainScaffold` whenever the user switches to a new tab. The `tab` property maps the actual screen index to a label: `home` (0), `messages` (1), `manage` (2), `directory` (3).

### Chat open / close tracking

In `RealChatScreen._navigateToChatView`, `chat_opened` is fired with `channel_id`, `channel_name`, and `organization_id` when a channel is tapped on narrow screens. `chat_closed` is fired with the same properties in the `.then()` callback when the user navigates back.

### API-level action tracking

`AmplitudeService.logEvent` calls were added to `SupabaseApiService` for the following user-intent actions (read-only and high-frequency operations were excluded to control costs):

| Event | Trigger |
|---|---|
| `sign_up` | `signUp` — account created successfully |
| `sign_up_error` | `signUp` — exception or creation failed |
| `login_error` | `signIn` / `signInWithProvider` — auth failure |
| `channel_followed` | `followOrganization` — success |
| `channel_follow_error` | `followOrganization` — exception |
| `channel_unfollowed` | `unfollowOrganization` — success |
| `channel_unfollow_error` | `unfollowOrganization` — exception |
| `post_reacted` | `upsertPostReaction` — success (includes emoji list) |
| `post_reaction_removed` | `removePostReaction` — success |
| `post_reaction_error` | `upsertPostReaction` / `removePostReaction` — exception |
| `direct_message_sent` | `sendDirectMessage` — success |
| `direct_message_error` | `sendDirectMessage` — exception |
| `profile_updated` | `updateUserProfile` — success (includes changed field names) |
| `feedback_submitted` | `submitFeedback` — success |
| `feedback_error` | `submitFeedback` — exception |

**Intentionally not tracked** (too frequent, would inflate event volume): all read operations (`getPostReactions`, `getCategoryCountsMap`, `getOrganizationFollowers`, etc.), FCM token management, session validation, and batch post-view inserts.

### Direct Messages tracking

`dm_chat_opened` and `dm_chat_closed` are fired in `_navigateToChatView` of `DirectMessagesScreen`, with `conversation_id`, `organization_id`, and `organization_name`. `dm_conversation_started` fires on both user and admin paths when a new conversation is successfully created, carrying `organization_id`, `organization_name`, and `role` (`user`/`admin`). `dm_conversation_start_error` fires on any failure path in `_startNewConversation`, `_startNewConversationAsAdmin`, and `openOrCreateConversation`, with `organization_id`, `error`, and `role`.

### Profile settings tracking

All tappable items in `SettingsScreen` now fire `profile_screen_tapped` with an `item` property: `edit_profile`, `account_settings`, `channels_followed`, `send_feedback`, `about`, `terms`, `privacy_policy`, `sign_out`.

### Notification badge tracking

`badge_updated` is fired inside `ChatService.updateNotificationBadgeFromChannels` every time the iOS/Android notification badge is written, carrying `count` (unread channels) and `total_channels`. This is the single authoritative badge-update path, so all callers (ChatBloc, RealChatScreen, ChannelsList, etc.) are covered without additional instrumentation.
