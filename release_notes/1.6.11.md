# Detailed Changes

### Cars feature (`lib/modules/cars/`)

- New `CarsSearchScreen` (`lib/modules/cars/cars_search_screen.dart`) — scrollable filter form added as a 4th bottom navigation tab (`Icons.directions_car`, label "Cars")
- **Make section** — 3×3 grid of featured brands (Toyota, Ford, Honda, Chevrolet, BMW, Mercedes-Benz, Tesla, Jeep) plus an "All Makes" tile; selecting a brand highlights it with a badge and unlocks the Model chips below
- **All Makes picker** (`_BrandPickerSheet`) — `DraggableScrollableSheet` at 92 % screen height with: live search field, horizontal alphabet carousel (`A–Z`), per-letter brand list showing logo + model count subtitle; supports brand deselect by re-tapping
- **Brand logos** — real PNG logos from `assets/car_logos/` for all 39 brands that have artwork; falls back to colored initials avatar for unlisted brands (currently Ineos)
- **18 filter sections**: Make, Model, Trim/Version (free text), Year Range (range slider 1980–2026), Specific Years (add/remove year tags), Price (range slider $0–$200K), Mileage (range slider 0–300K km), Body Type, Fuel Type, Transmission, Drivetrain, Engine Size, Power Steering, Doors, Color (swatches with labels), Features & Options, Condition & History, Sort By
- Active filter counter shown in AppBar reset button; Search button reflects applied count
- `CarData` static class (`lib/modules/cars/car_data.dart`) — brand→models map (40 brands, 400+ models), `brandLogoFiles` map for asset lookup, and all filter option constant lists
- `assets/car_logos/` registered in `pubspec.yaml`

### OTP fix (`lib/services/auth_pending_otp_service.dart`, `lib/modules/auth/auth_bloc.dart`)

- `AuthPendingOtpService` introduced to persist the in-flight OTP verification context (email, flow type) across app lifecycle events
- `AuthBloc` now restores pending OTP state on cold start / foreground resume, preventing users from being silently dropped out of the verification flow when the app is closed mid-OTP
- Extended `AuthPendingOtpService` with SMS-specific persistence (`savePhone` / `clearPhone` / `getPhone`, keys `pending_sms_phone` / `pending_sms_email`) — fixes BUG-004 (app killed while waiting for SMS) and BUG-005 (app killed immediately after submitting SMS code)
- `AuthBloc._onChoosePhoneVerification` now calls `savePhone` before emitting `AuthPendingPhoneVerificationState` so the phone number and email survive an app kill
- `AuthBloc._onCheckAuthStatus` restores `AuthPendingPhoneVerificationState` on restart when the user is unverified and a persisted SMS OTP record is found (valid session path); clears stale SMS state and falls back to welcome when the session is gone (all SMS operations require an authenticated session)
- `AuthBloc._onVerifyPhoneOtp` calls `clearPhone` on successful verification

### Admin promotion database fixes (`migrations/069_fix_auth_uid_in_security_definer.sql`, `migrations/070_debug_promote_auth.sql`)

- Migration 069 — corrects `auth.uid()` resolution inside `SECURITY DEFINER` functions: the previous fix (migration 068) used `auth.uid()` but the function's security context bypassed the `auth` schema visibility, causing `NULL` caller IDs; replaced with an explicit `current_setting('request.jwt.claims', true)` extraction
- Migration 070 — adds temporary diagnostic logging to `promote_user_to_admin` to surface caller identity and role at promotion time; aids QA verification of the authorization chain
