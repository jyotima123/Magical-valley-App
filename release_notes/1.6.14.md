# 1.6.14

- Feature (QA): Cars search now works — the search bar filters listings as you type (make, model, trim, year, stock, color, location…), and the filter panel actually applies: it returns the selected filters to the list, shows a live "X of Y vehicles match" count, remembers its state when reopened, and supports all sort options
- Feature (QA): "Other" make/model — both dropdowns in the listing form now include an *Other* option that reveals a free-text field, so vehicles outside the built-in `CarData` catalog can be listed
- Feature (QA): edit a listing — the ad creator sees an edit button on the vehicle detail screen; the form opens pre-filled and updates the existing row instead of inserting
- Feature (QA): stock numbers are auto-generated — manual Stock field removed; new listings get `max(1000, highest existing numeric stock) + 1` with retry on collision
- Feature (QA): mark as sold — the creator can mark/unmark a listing as sold; sold cards render dimmed with a red SOLD overlay, can't be opened by other users, and hide the Call / Message Seller actions
- Feature (QA): push notifications for cars chat — vehicle inquiry messages now trigger FCM pushes to the other participant, with tap-to-open navigation into the chat, an in-app banner for foreground messages, and a new `vehicle-inquiry` deep link handled by the auth signal chain
- Feature (QA): send pictures in cars chat — attach button in the vehicle inquiry chat uploads photos (multi-select, HEIC→PNG conversion) and renders them as image bubbles with fullscreen pinch-zoom view
- Fix (BUG-004/BUG-005): SMS verification no longer fails with "Auth session missing" — phone OTP calls now wait for the cold-start session restore (and refresh an expired token) before hitting Supabase, with a friendly error if the session truly can't be recovered
- Fix (BUG-007, security): a logged-in user opening *another* user's password reset link can no longer change that user's password — the link's account is compared to the active session and mismatches are rejected with an explicit error
- Fix (BUG-008/BUG-009): expired, already-used, or tampered reset links are now rejected the moment the link is opened (token verified at link-open, not at submit) and show a dedicated error screen — no more reset form for dead links and no more random bounces to the Welcome screen. ⚠️ Requires a Supabase dashboard change for the 1-hour expiry: **Authentication → Email → "Email OTP expiration" = 3600s** (likely still at the 24h default)
- Behaviour change for QA: reset links are single-use and consumed **when opened** — reopening an abandoned link shows the error screen instead of the reset form (affects the DL-108 expectation that an unsubmitted link stays usable)

# Detailed Changes

### Cars search (`lib/modules/cars/`)

- `vehicle_search_filters.dart` (new): `VehicleSearchFilters` value object shared by the list and filter screens — holds brand/models/trim, year range + specific years, price/mileage ranges (with "Any" ceilings), chip sets (body, fuel, transmission, doors, colors…), and sort; `matches(VehicleListing)` applies column-backed filters exactly and free-form ones (drivetrain, engine size, steering, features, condition) against the listing's descriptive text; `sort()` implements all `CarData.sortOptions`
- `vehicles_screen.dart`: fake search bar replaced with a live `TextField` (client-side filtering, clear button); tune icon opens `CarsSearchScreen` and applies the returned filters; active-filter badge on the icon plus an "N filters applied / Clear all" bar; dedicated "No vehicles match your search" empty state with one-tap reset
- `cars_search_screen.dart`: accepts `initialFilters` + the loaded listings; results bar shows a real "X of Y vehicles match your filters" count that updates as filters change; the Search button pops with the built `VehicleSearchFilters` (previously showed a "search coming soon" snackbar)

### Add / Edit listing (`lib/modules/cars/add_vehicle_screen.dart`)

- Make dropdown now ends with *Other* → shows a required "Make (type manually)" field; model becomes free text when make is custom, and known makes get an *Other* entry in the model dropdown with the same manual field
- Screen accepts an optional `existing: VehicleListing` — pre-fills every field (custom makes/models resolve back to *Other* + text, photos load into the strip), title switches to "Edit Listing", and save runs `update().eq('id', …)` instead of `insert()`
- Stock field replaced by a read-only info row ("Auto-generated on save" / the actual number when editing); on insert the next stock is computed as `max(1000, highest numeric stock) + 1`, retried up to 3× on unique-constraint collision
- `lib/modules/cars/vehicle_detail_screen.dart`: owner-only edit icon in the app bar; the screen now holds mutable listing state and re-fetches from `vehicle_listings` after an edit; the vehicles list reloads when returning from the detail screen
- `migrations/074_vehicle_listing_sold_and_creator_edit.sql` (new): RLS policy "Creators can update their own vehicle listings" (`auth.uid() = created_by`) — editing previously required the admin role

### SMS verification "Auth session missing" (BUG-004 / BUG-005)

- Root cause: `sendPhoneOtp()` calls `auth.updateUser(phone:)`, which throws `AuthSessionMissingException` when invoked while gotrue is still restoring the persisted session after an app kill (the restore is asynchronous) or when the access token has expired — the earlier fix guarded `getCurrentUser()` but not the SMS calls themselves
- `lib/services/api/supabase_api_service.dart`: new `_ensureSession()` helper polls briefly for the cold-start session recovery and refreshes an expired token; `sendPhoneOtp` / `verifyPhoneOtp` / `resendPhoneOtp` now run behind it and catch `AuthSessionMissingException` with an actionable message instead of surfacing "Auth session missing!"

### Password reset deep links (BUG-007 / BUG-008 / BUG-009)

- Root cause: the recovery token was only verified when the user tapped UPDATE PASSWORD, so the reset screen appeared for *any* token (expired/used included) and User A's device could still consume User B's token at submit time; the erratic "1st attempt → Welcome" behaviour was `logout()`/`signOut()` firing `signedOut` events whose queued `NavigateToHomeEvent` (or the cold-start `appStart` check) stomped the reset screen
- `lib/modules/auth/auth_bloc.dart`: `_onPasswordResetLinkReceived` rewritten — snapshots the signed-in user, then verifies (and thereby consumes) the single-use token **at link-open time** via the new `verifyRecoveryToken()`; invalid/expired/used tokens → explicit error state; link account ≠ active account → sign out + error, the link owner's password is never changed (DL-103); only a valid, matching link reaches `AuthPasswordResetState`
- `lib/modules/auth/chain/handlers/flow_guard_handler.dart`: new static `linkFlowActive` flag guards the whole link-processing window (before `AuthPasswordResetState` exists to check against); while set, ambient Supabase auth events are swallowed and `_onCheckAuthStatus` early-returns — auto-cleared by `AuthBloc.onChange` when the flow's states end, and the flow finishes via the new `PasswordResetFlowCompleteEvent` (success dialog / error screen button) which re-runs the auth check
- `lib/modules/auth/reset_link_error_screen.dart` (new): explicit terminal screen for unusable links (expired / used / tampered / different account) with a CONTINUE button — replaces the silent Welcome bounce (DL-104/105/106 want a clear error)
- `lib/modules/auth/reset_password_screen.dart`: no longer re-verifies the token at submit — `_resetPassword()` uses the recovery session created at link-open (`setNewPassword` → `signOut`); back arrow now discards the recovery session via `GoBackEvent`
- DL-108 safety: verifying a token creates a *real* Supabase session, so `AuthPendingOtpService` gains a `pending_password_recovery` marker and the restoration chain gets `InterruptedRecoveryRestorationStep` (runs first) — if the app is killed on the reset screen, the leftover recovery session is signed out on next launch instead of silently logging the user in without a password
- `lib/services/api/supabase_api_service.dart`: `signInViaMagicLink()` removed in favour of `verifyRecoveryToken()` (distinguishes network failures, which leave the token usable, from invalid/expired tokens)
- ⚠️ Server-side action required for BUG-008: link age cannot be enforced client-side — set Supabase Dashboard → **Authentication → Email → "Email OTP expiration"** to **3600** seconds
