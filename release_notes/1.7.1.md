# 1.7.1

- Feature: vehicle detail screen now shows the seller at the far right of the Stock # row — the dealership name for feed inventory, or the name of the person who posted it for a community listing
- Feature: sellers can delete their own listing from the app — a Delete icon next to Edit on the vehicle detail screen, and a Delete item in each vehicle's menu on My Listings
- Feature: a sold community listing now clears itself from the shared Cars list 24h after the sale, instead of sitting there indefinitely; the seller's own copy still shows in My Listings regardless
- Feature: "Mark as Sold" moved out of the vehicle detail app-bar menu into the main action row, in the slot a buyer's Call button occupies — owners see Mark as Sold + View Messages, buyers see Call + Message Seller
- Feature: the Cars list now puts a seller's own listings first, ahead of everyone else's, whatever sort is selected

# Detailed Changes

### Vehicle detail (`lib/modules/cars/vehicle_detail_screen.dart`)

- New `_loadSellerName()`, kicked off from `initState` and applied via `setState` once it resolves, so the row stays blank rather than blocking the rest of the screen:
  - Dealer-feed vehicles (`isFromDealerFeed`): reads `dealer_sources.display_name` for the listing's `source`
  - Community listings: calls `ApiRepository.getUserProfile(createdBy)` and prefers `full_name`, falling back to `username`
- The `Stock #<stock>` text moved into a `Row` with `MainAxisAlignment.spaceBetween`; the seller name renders on the right when the lookup succeeds, otherwise the row is unchanged
- Best-effort only: a failed or empty lookup is swallowed silently, matching how the rest of the screen already treats `_reload()` failures
- New `_deleteListing()`: confirms, soft-deletes via `vehicle_listings.deleted_at`, then pops back to the previous screen. A real `DELETE` was ruled out — `vehicle_inquiry_conversations.vehicle_id` cascades on delete (migration 073), so it would wipe out a buyer's chat history with that car. No new RLS policy needed; a soft delete is just an `UPDATE`, already covered by the existing creator-update policy
- The app-bar popup menu (previously just "Mark as Sold") is now a plain Delete icon next to Edit, with a confirm dialog and its own spinner state (`_deletingListing`)
- "Mark as Sold" / "Mark as Available" moved into the main action row: for the owner it now renders in the slot a buyer's Call button would occupy (which would otherwise have let an owner "call" their own number), with its spinner inline on the button instead of in the app bar

### Community vehicle provider (`lib/modules/cars/providers/community_vehicle_provider.dart`)

- Query now excludes `deleted_at IS NOT NULL` rows, and excludes a sold listing once `sold_at` is more than 24h old (`is_sold.eq.false,sold_at.gt.<cutoff>`) — `sold_at` is set by a DB trigger the instant `is_sold` flips true, not by the app, so the window can't drift from an unrelated edit

### My Listings (`lib/modules/market/my_listings_screen.dart`, `lib/modules/market/market_repository.dart`)

- New `MarketRepository.deleteVehicle()` (soft delete, same `deleted_at` column) and a `Delete` entry in the row menu, vehicle listings only — deleting a Market item is out of scope for this pass
- `fetchVehiclesBy()` now excludes deleted rows; sold ones are unaffected and keep showing here indefinitely, since this is the seller's own history rather than the shared browse list

### Cars list (`lib/modules/cars/vehicles_screen.dart`)

- `_recomputeMatches()` does a stable partition after `_filters.sort()`: the signed-in user's own listings come first, then everyone else's, preserving whatever sort order was chosen within each half

### Database (`migrations/085_vehicle_listing_delete_and_sold_expiry.sql`)

- Adds `vehicle_listings.deleted_at` (soft delete) and `vehicle_listings.sold_at`
- `vehicle_listings_sold_at` trigger sets `sold_at = now()` when `is_sold` flips true, clears it when flipped back
- Backfills `sold_at = updated_at` for rows that were already sold, so they start aging out of the 24h window immediately rather than being treated as sold "just now"
- Applied directly against the live database (not via CI)
