# 1.6.13

- Feature (QA): Vehicle Detail screen — tapping a vehicle card in the Cars tab opens a full detail view with image gallery, specs, appearance, description, options, and pricing
- Feature (QA): Vehicle Inquiry messaging — buyers can message a seller directly from a vehicle listing; sellers see all inquiry conversations for their listing via "View Messages"
- Feature (QA): Contact phone field on vehicle listings — optional phone number shown on the detail screen with a tap-to-call button
- Database: new `vehicle_inquiry_conversations` and `vehicle_inquiry_messages` tables for user-to-user messaging scoped to a vehicle listing, separate from the org DM system

# Detailed Changes

### Vehicle Detail screen (`lib/modules/cars/vehicle_detail_screen.dart`, new)

- `SliverAppBar` with swipeable `PageView` image gallery, dot indicators, and photo counter badge; falls back to a make-labelled placeholder when no photos exist
- Header card shows status badge, title, price (with promotional strikethrough), stock number, location, and contact phone
- "Call" button (via `url_launcher`) appears when a contact phone is set; "Message Seller" button creates or resumes a vehicle inquiry conversation — switches to "View Messages" when the current user owns the listing
- Sections: Overview (spec chips with icons), Specifications (key-value table), Appearance, Description, Options & Packages — each section only renders when data is present

### Vehicle list tap-to-detail (`lib/modules/cars/vehicles_screen.dart`)

- Each `_VehicleCard` in the listing `ListView` is now wrapped in a `GestureDetector` that pushes `VehicleDetailScreen` with the tapped listing

### Contact phone column (`migrations/072_vehicle_listing_contact_phone.sql`, new)

- Adds `contact_phone text` column to `vehicle_listings`
- `VehicleListing` model updated with `contactPhone` field in constructor, `fromJson`, and `toJson`
- `AddVehicleScreen` includes a "Contact Phone" text field in the Details section; value is persisted on save

### Vehicle Inquiry messaging system (`migrations/073_vehicle_inquiry_messages.sql`, new)

- `vehicle_inquiry_conversations` table — links a `buyer_id`, `seller_id`, and `vehicle_id`; unique constraint on `(vehicle_id, buyer_id)` ensures one conversation per buyer per listing
- `vehicle_inquiry_messages` table — same shape as org DMs (text/image/pdf, `is_read` tracking, file constraint)
- RLS policies: both participants (buyer + seller) can view, send, and update messages; superadmins have full access
- `vehicle_inquiry_conversations_view` joins vehicle summary, buyer/seller profiles, and last message for the Flutter list
- Realtime enabled on both tables; `updated_at` auto-triggers and conversation touch-on-message trigger match the org DM pattern
- `get_vehicle_inquiry_unread_count()` helper function for per-conversation unread counts

### Vehicle Inquiry chat screen (`lib/modules/cars/vehicle_inquiry_chat_screen.dart`, new)

- Vehicle banner at top showing thumbnail, title, and price
- App bar displays the other participant's name with the vehicle title as subtitle
- Real-time message stream via `streamVehicleInquiryMessages`; auto-scrolls on new messages; marks incoming messages as read
- Message bubbles with sender-aware styling (accent-coloured for outgoing, white for incoming), timestamps in 12-hour format

### Vehicle Inquiries list screen (`lib/modules/cars/vehicle_inquiries_list_screen.dart`, new)

- Shown when the listing owner taps "View Messages"; fetches all inquiry conversations for that vehicle via `getVehicleInquiriesForListing`
- Each tile shows the buyer's avatar (or initial fallback), name, last message preview, and relative timestamp
- Tapping a tile opens `VehicleInquiryChatScreen`; empty state when no buyers have messaged yet

### API layer (`lib/services/`)

- `ApiService` (abstract): added `createOrGetVehicleInquiry`, `getVehicleInquiries`, `getVehicleInquiriesForListing`, `getVehicleInquiryMessages`, `sendVehicleInquiryMessage`, `markVehicleInquiryMessagesAsRead`, `streamVehicleInquiryMessages`
- `SupabaseApiService`: implementations hit the `vehicle_inquiry_conversations` / `vehicle_inquiry_messages` tables and the conversations view; `DirectMessageItem` model is reused for messages (same schema)
- `ApiRepository`: passthrough methods for all seven new operations

### Vehicle Inquiry model (`lib/modules/cars/vehicle_inquiry_conversation.dart`, new)

- `VehicleInquiryConversation` with vehicle summary fields (year, make, model, trim, price, image URL), buyer/seller profile fields, last message via `ChatMessage`, and `vehicleTitle` helper
