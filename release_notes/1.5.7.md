# 1.5.7

- Fixed email/sms verification being triggered for Apple login users

# Detailed Changes

### Fix 1 — Social login users (_onCheckAuthStatus)

getCurrentUser() was returning userMetadata (user-set data), not appMetadata (server-set, contains provider). Now it merges both, so _onCheckAuthStatus can read user.userData['app_metadata']['provider'].

If the provider is not 'email' (i.e. Apple/Google/Facebook), the verification check is skipped entirely. If verified_at is still null for that social user (they signed up before migration 059), it's backfilled
silently in the background.

### Fix 2 — Migration 057 not run

PostgREST with select('*') omits columns that don't exist — a missing verified_at column produces no key in the JSON, while an existing-but-null column produces "verified_at": null. So json.containsKey('verified_at')
reliably distinguishes the two cases. If the key is absent → column not there → treat the user as pre-verified (DateTime(2000)). Existing users never see the verification screen.

### Fix 3 — Migration 059 (new)

The handle_new_user trigger now sets verified_at = NOW() for any non-email provider at signup time, so social users are clean from day one. The migration also backfills existing social users whose verified_at is still
null.
